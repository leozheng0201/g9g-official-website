# 第五階段｜LINE 禮物官方資料整合與私人預覽設計

## 1. 目標

在不修改 `main`、不發布正式站的前提下，將《2026 LINE 禮物資訊分享》中的官方資訊整合進 G9G 官網，建立一個可被品牌理解、可被搜尋引擎索引、又不會讓人誤認 G9G 為 LINE 官方或官方代理商的內容入口。

本階段採用方案 B：新增獨立「認識 LINE 禮物」頁，首頁只放精簡信任區；LINE 禮物研究院負責後續延伸文章。

## 2. 資料來源與內容邊界

主要資料來源：使用者上傳的《2026 LINE 禮物資訊分享》。

可使用的官方資訊包括：

- 2021–2025 累積送出超過 8,000 萬份禮物。
- LINE 禮物用戶超過 900 萬。
- 20–44 歲用戶占比超過八成。
- 34 歲以下族群超過 55%。
- 女性／男性用戶約為 60%／40%。
- 2026 社交送禮四大場景：儀式、商務、吉時、情緒。
- 成長公式：商品 × 流量 × 轉換。
- 年度方向：更好逛、更心動、更好送。

不得把下列內容寫成 LINE 官方結論：

- G9G 對選品、價格、包裝、商品頁、檔期與版位的推論。
- 品牌是否適合進駐 LINE 禮物。
- 業績、流量、轉換率或搜尋排名保證。
- G9G／盛澄策略顧問與 LINE 的官方合作、授權或代理關係。

## 3. 網站資訊架構

### 3.1 新增獨立頁

路由：`/about-line-gift`

頁面標題：認識 LINE 禮物

SEO 主題：

- LINE 禮物是什麼
- LINE 禮物用戶
- LINE 禮物市場
- LINE 禮物送禮場景
- LINE 禮物品牌經營

頁面不使用「官方網站」或「官方代理商」等可能造成誤認的字樣。

### 3.2 首頁信任區

首頁新增一個精簡區塊，放在 G9G 方法論之前或之後，不改動原本主要轉換動線。

顯示最多四項官方資訊：

- 900 萬以上用戶
- 8,000 萬以上累積送禮份數
- 20–44 歲用戶超過八成
- 四大社交送禮場景

區塊必須顯示「資料來源：2026 LINE 禮物資訊分享」，並連結至 `/about-line-gift`。

不得採用舊預覽稿中的「免費品牌健檢」文字；現行 CTA 維持「申請品牌成長健檢」。

### 3.3 LINE 禮物研究院

研究院首頁保留文章列表功能，並新增「先認識 LINE 禮物」入口卡片。

獨立頁是完整基礎介紹；研究院文章則負責延伸：

- 用戶輪廓
- 四大送禮場景
- 商品 × 流量 × 轉換
- 年度檔期
- 商品、包裝、價格與轉換實戰

不得在第一版建立沒有來源支持的文章內容。

## 4. 獨立頁內容結構

### 4.1 Hero

Eyebrow：LINE 禮物官方資料 × 老莊營運解讀

H1：認識 LINE 禮物：品牌進入送禮市場前，應該先看懂什麼？

說明：從官方市場資料、用戶輪廓、送禮場景與平台成長方向，整理品牌評估 LINE 禮物時需要理解的基礎。

主要 CTA：申請品牌成長健檢

次要 CTA：進入 LINE 禮物研究院

### 4.2 LINE 禮物與一般電商的差異

此段為 G9G 解讀，不標示為官方原文。

核心表達：一般電商主要解決「我需要什麼」；送禮電商還需要回答「我想對誰表達什麼」。

此段必須使用「老莊營運解讀」標籤。

### 4.3 官方市場數據

數據卡顯示：

- 900 萬以上用戶
- 8,000 萬以上累積送禮份數
- 20–44 歲超過八成
- 34 歲以下超過 55%
- 女性約 60%、男性約 40%

此區只呈現來源支持的數據，不加入 G9G 推估。

### 4.4 四大社交送禮場景

依官方資料使用以下順序與名稱：

1. 儀式禮物
2. 商務禮物
3. 吉時禮物
4. 情緒禮物

每個場景分為兩層：

- 官方資料：場景名稱與官方資料可支持的定義。
- 老莊解讀：對商品、包裝、價格、文案或檔期的營運意義。

### 4.5 成長公式

官方框架：商品 × 流量 × 轉換。

G9G 解讀：

- 商品：送禮理由、對象、價格帶、組合、包裝與賀卡。
- 流量：平台活動、年度檔期、主題策展、品牌週與站內版位。
- 轉換：首圖、標題、商品頁、優惠、加價購、客製化與收禮者選擇。

G9G 解讀不得標示為 LINE 官方建議。

### 4.6 2026 平台方向

使用官方用語：

- 更好逛
- 更心動
- 更好送

每項下方另設「老莊解讀」，說明品牌可能對應的執行方向；不得把解讀寫成官方承諾。

### 4.7 三層信任架構

固定三欄：

1. LINE 禮物官方資料
2. 老莊的營運解讀
3. G9G 可以怎麼協助

第三欄可連結：

- 品牌成長健檢
- 品牌成長藍圖
- 品牌成長代營運

### 4.8 聲明與來源

頁面底部必須固定顯示：

> 資料來源：《2026 LINE 禮物資訊分享》。G9G／盛澄策略顧問非 LINE 官方或官方代理商；本頁將官方資料、營運解讀與 G9G 服務分開呈現。

不得顯示 LINE 帳號名稱 `scrutator` 或 QR Code。

## 5. 視覺與元件

延續現有明亮、乾淨的 G9G 官網，不採用舊黑底預覽稿。

LINE 綠只作為重點色，不模仿 LINE 官方網站版型。

三種內容來源使用固定視覺標籤：

- 官方資料：中性色／資料圖示
- 老莊解讀：G9G 品牌色／觀點圖示
- G9G 協助：CTA 卡片

數據卡與場景卡在手機版改為單欄或雙欄，不得橫向溢出。

## 6. CMS 與內容維護

第一版頁面內容由 CMS 管理，不建立第二套靜態內容來源。

建議建立一篇 `line_gift_academy` 類型的正式內容，slug 為 `about-line-gift`，並以 publication snapshot 提供公開頁讀取。

固定頁路由 `/about-line-gift` 讀取該發布快照；未發布時回傳可控的預覽狀態，不把草稿公開。

首頁精簡數據可以使用共用內容常數或 CMS 精選欄位，但必須只有單一維護來源。優先由該內容的 `type_fields` 提供首頁精選數據。

## 7. SEO 與索引

正式內容完成後應具備：

- 唯一 H1
- title 與 meta description
- canonical `/about-line-gift`
- BreadcrumbList
- Article 或 WebPage 結構化資料
- 加入 sitemap
- 研究院與首頁內部連結

私人 Preview 必須：

- `noindex, nofollow`
- 不加入 sitemap
- 不更新 Production
- 清楚顯示「未公開預覽」

## 8. 驗收標準

### 8.1 內容

- 所有數據均可回溯至上傳的官方資料。
- 官方資料、老莊解讀與 G9G 協助視覺與文字分層清楚。
- 頁面明確聲明 G9G／盛澄不是 LINE 官方或官方代理商。
- 不出現「免費品牌健檢」。
- 不出現未核准的業績保證、搜尋排名保證或官方合作暗示。

### 8.2 功能

- `/about-line-gift` 正常顯示已發布內容。
- 草稿或未發布內容不出現在公開頁與 sitemap。
- 首頁信任區連結正確。
- 研究院入口連結正確。
- 桌機與 390px 手機版無橫向溢出。

### 8.3 測試

- 單元測試驗證官方數據、來源聲明與非官方聲明。
- 單元測試驗證首頁精簡區只使用核准數據。
- Playwright 驗證桌機、手機、canonical、noindex Preview 與內部連結。
- 完整 CI：lint、typecheck、unit、build、Playwright、Supabase migration、pgTAP、database lint。

## 9. 發布邊界

本階段只合併至 `develop`。

不得：

- 合併至 `main`
- 發布 Production
- 開放搜尋引擎索引私人 Preview
- 宣稱已正式上線

完成後提供私人桌機版與手機版預覽，待使用者確認後再另行決定正式上線時間。
