# G9G 官方網站 V2.0 Implementation Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement each child plan task-by-task. Steps in child plans use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 依照已核准設計規格，分階段交付可正式營運的 G9G 多分頁企業官網、專屬 CMS、品牌成長健檢流程、SEO 與發布系統。

**Architecture:** 單一 Next.js App Router 專案同時承載公開網站與 `/admin` 後台；Supabase 提供 PostgreSQL、Auth、Storage 與 RLS。各子系統以資料模型、server-side service、UI route group 與測試邊界拆分，每一階段都產生可獨立驗收的軟體版本。

**Tech Stack:** Node.js 24 LTS、Next.js 16.2.12、React 19.2.8、TypeScript 7.0.2、Tailwind CSS 4.3.3、Supabase JS 2.110.8、Supabase SSR 0.12.3、Zod 4.4.3、Vitest 4.1.10、Testing Library 16.3.2、Playwright 1.62.0、Vercel。

## Global Constraints

- 全站不得使用「免費」形容品牌成長健檢。
- 品牌健檢統一名稱為「品牌成長健檢」，主要 CTA 為「申請品牌成長健檢」。
- 第一階段健檢表單只收集：聯絡人姓名、品牌名稱、手機、Email、品牌連結、隱私權同意與隱藏 honeypot。
- 前台每一段文字、圖片、按鈕與 SEO 欄位都必須有後台對應位置。
- 前台採固定版型 CMS；管理者可改內容、顯示、排序與媒體，但不可任意破壞版面。
- 所有內容型資料支援草稿、預覽、發布、下架、封存與版本紀錄。
- 權限必須由 Supabase RLS 與 server-side 驗證雙重保護，不能只靠隱藏 UI。
- 未串接真實分析來源前，Dashboard 不顯示虛構流量或 SEO 數據。
- 平台數據必須保存來源名稱、來源年份、最後查核日期與查核狀態。
- 正式部署前必須通過 lint、typecheck、unit、integration、build、database policy tests 與 Playwright smoke tests。
- `main` 為正式環境、`develop` 為整合預覽、`feature/*` 為功能分支。

## Delivery Map

### Plan 1｜Foundation

**Plan file:** `docs/superpowers/plans/2026-07-30-g9g-v2-foundation.md`

**Scope:**

- Next.js 專案初始化與版本鎖定
- Node、npm、ESLint、TypeScript、Tailwind、Vitest、Playwright
- Design tokens 與基本 UI primitives
- Supabase 本機環境、基礎 migration、Auth、SSR session refresh
- RBAC 基礎、管理後台 shell、audit event 基礎
- GitHub Actions quality gate 與本機開發文件

**Acceptance gate:**

- 公開首頁可開啟。
- `/admin` 未登入會導向 `/admin/login`。
- 已登入但無角色者無法進入管理區。
- super admin 可看見 Dashboard shell。
- RLS 測試證明一般使用者不能提升自己權限。
- lint、typecheck、unit、build、DB tests、E2E smoke 全部通過。

### Plan 2｜Public Website

**Planned file:** `docs/superpowers/plans/2026-07-30-g9g-v2-public-website.md`

**Scope:**

- Header、mega navigation、mobile drawer、Footer、Breadcrumb
- 首頁、關於 G9G、為什麼選擇 G9G
- 品牌成長健檢、品牌成長藍圖、品牌成長代營運
- 聯絡、隱私權、網站使用條款、404
- RWD、Accessibility、基礎 SEO metadata 與 Organization/WebSite Schema

**Acceptance gate:**

- 所有主要頁面都有獨立 URL，不呈現一頁式感受。
- 桌面與手機導覽均可完整到達所有主頁。
- 全站搜尋不到用來形容健檢的「免費」。
- Lighthouse accessibility 與 SEO 不低於 90（Preview 環境）。

### Plan 3｜Content CMS

**Planned file:** `docs/superpowers/plans/2026-07-30-g9g-v2-content-cms.md`

**Scope:**

- LINE 禮物研究院
- 品牌觀點
- 品牌成長案例
- FAQ
- 品牌資源中心
- 分類、標籤、相關內容、來源治理
- 媒體中心與 private/public bucket 規則
- 列表、編輯、預覽與前台內容頁

**Acceptance gate:**

- 五種內容均可新增、編輯、預覽與在前台顯示。
- 首頁精選與列表頁共用同一筆案例或文章資料。
- FAQ 可在 FAQ 頁與服務頁重複引用而不重複維護。
- 未確認平台數據不可發布成無來源事實。

### Plan 4｜Growth Audit

**Planned file:** `docs/superpowers/plans/2026-07-30-g9g-v2-growth-audit.md`

**Scope:**

- 品牌成長健檢第一階段表單
- Server-side Zod 驗證、honeypot、rate limit
- 申請狀態流程與後台管理
- 內部備註、操作紀錄與角色限制
- 管理通知、申請人確認信、成功頁

**Acceptance gate:**

- 正常申請可儲存並寄出兩封正確通知。
- 垃圾訊息、重複快速提交與不合法資料被拒絕。
- 只有 Super Admin 與 Service 可讀取完整個資與內部備註。
- 確認信不承諾申請人一定取得健檢名額。

### Plan 5｜Page CMS

**Planned file:** `docs/superpowers/plans/2026-07-30-g9g-v2-page-cms.md`

**Scope:**

- 固定版型 `pages` 與 `page_sections`
- 首頁與企業頁區塊編輯
- 導覽、頁尾、全站 CTA、聯絡資訊
- 網站設定、分析 ID、社群、公司資訊
- 媒體選擇、ALT、顯示、排序與 preview

**Acceptance gate:**

- 所有前台固定文案與圖片都有後台欄位。
- 管理者無法建立未定義的任意版型。
- 公司資料未填時不顯示空欄位。
- 修改草稿不會直接影響正式前台。

### Plan 6｜Revisions & Publishing

**Planned file:** `docs/superpowers/plans/2026-07-30-g9g-v2-revisions-publishing.md`

**Scope:**

- `draft`、`scheduled`、`published`、`unpublished`、`archived`
- Preview token 與草稿預覽
- 發布、下架、封存
- 發布前 snapshot、版本列表、diff 摘要、還原

**Acceptance gate:**

- 每次發布前都有不可變 snapshot。
- 還原會建立新版本，不覆蓋或刪除歷史。
- 已發布 slug 改變後，舊網址正確 301 到新網址。
- 封存內容不出現在前台與 sitemap，但仍可在後台還原。

### Plan 7｜SEO & Analytics

**Planned file:** `docs/superpowers/plans/2026-07-30-g9g-v2-seo-analytics.md`

**Scope:**

- 每頁 SEO title、description、canonical、OG、index、sitemap 控制
- Article、FAQPage、Breadcrumb、Organization、WebSite JSON-LD
- 動態 sitemap、robots、redirect
- 事件追蹤與主要／次要轉換

- 發布／下架會同步更新 sitemap。
- 未設定 GA4、Search Console、Clarity 時不注入追蹤程式，也不顯示假數據。

### Plan 8｜Hardening & Release

**Planned file:** `docs/superpowers/plans/2026-07-30-g9g-v2-hardening-release.md`

**Scope:**

- RLS 完整 policy matrix 與 database policy tests
- Security headers、上傳限制、錯誤日誌、敏感資料遮罩
- 效能、圖片、cache、可用性與無障礙
- Preview／Production 環境與 Vercel 部署
- Supabase migration release 流程與備份
- 發布 smoke test、營運手冊、後台操作手冊

**Acceptance gate:**

- 全部 quality gates 通過。
- Preview 驗收完成後才允許合併 `main`。
- Production migration、網站、後台、表單、Email、sitemap、robots、canonical 均完成發布後檢查。
- 可由非工程人員依操作手冊新增文章、案例、FAQ、資源與修改固定頁面內容。

## Dependency Order

```text
Foundation
├── Public Website
├── Content CMS
├── Growth Audit
└── Page CMS
     └── Revisions & Publishing
          └── SEO & Analytics
               └── Hardening & Release
```

Public Website、Content CMS、Growth Audit、Page CMS 可在 Foundation 完成後以不同 `feature/*` 分支並行，但 Revisions & Publishing 必須等待內容與頁面資料模型穩定；SEO & Analytics 必須等待公開路由與發布流程完成；Hardening & Release 最後執行。

## Review Checkpoints

1. **Foundation checkpoint:** 專案可安裝、可測試、Auth/RBAC/RLS 基礎成立。
2. **Public checkpoint:** 多分頁前台與手機導覽可完整瀏覽。
3. **CMS checkpoint:** 內容新增、預覽、發布與前台呈現可用。
4. **Lead checkpoint:** 品牌成長健檢流程、通知與後台狀態可用。
5. **Publishing checkpoint:** 草稿、版本、還原、封存、redirect 可用。
6. **Release checkpoint:** SEO、安全、效能、部署與營運文件全部驗收。

## Roadmap Definition of Done

V2.0 只有在以下條件全部成立時才可標示 Release：

- 所有設計規格驗收條件均有對應自動測試或人工驗收紀錄。
- `npm run lint`、`npm run typecheck`、`npm run test`、`npm run build`、`npm run db:test`、`npm run test:e2e` 全部成功。
- 前台、後台、表單、Email、RLS、版本還原、SEO 與手機版皆完成 Preview 驗收。
- 未完成或未連接的外部系統以清楚狀態顯示，不使用假資料替代。
- 正式網域與 canonical 未確認前，不開始累積正式 SEO 訊號。
